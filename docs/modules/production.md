# 生产出货模块

> **适用范围**：`生产出货` Tab → `下单生产`阶段（`STAGES[9]`）
> **核心文件**：`src/features/detail/index.tsx` 的 `TabProd` / `computeBatch()`
> **状态管理**：`src/context/ProductContext.tsx`
> **存储方式**：随产品 JSON 保存到 SQLite `products` 表

## 1. 模块目的

模块同时追踪采购合同、供应商付款和实际出货。三个问题必须分开回答：

1. **采购合同最终承诺多少？**
2. **已实际出货、截至当前已形成多少应结？**
3. **已付多少、当前还需要支付多少？**

旧版本用会随出货状态切换的单一“结算金额”回答上述问题，部分出货时容易把尚未履约的合同承诺隐藏掉。当前版本将合同、履约和现金口径拆分。

## 2. 数据模型

```
ProductionBatch
├── 基本信息：batchNo / factory / orderDate / expectedShip
├── 货值：qty + unitPrice，或 items[]（变体 SKU）
├── extraCosts[]：其他费用
├── depositActual / balancePayments[]：实际付款
└── shipments[]：出货记录；shipDate 是实际履约的生效开关
```

### 2.1 其他费用

每条费用包含 `name`、`qty`、`unitPrice`，并可选择进入已出货结算的方式：

| 归属方式 | 规则 |
|---|---|
| 按数量分摊（新建默认） | 按累计实际出货量占下单量的比例确认；超量出货不会重复确认费用。 |
| 首次出货计入 | 第一条填有实际出货日期的记录一次性确认全部费用。 |
| 指定出货计入 | 仅在指定的、已实际出货的记录中确认。 |

历史费用没有 `allocation` 字段时，按“首次出货计入”解释，保证重构后历史批次金额不变。费用可为负数，例如供应商违约赔付扣款。

### 2.2 付款

- `depositActual` 是实际预付款。
- `balancePayments[]` 记录多笔尾款；旧单笔 `balanceAmt` / `balanceDate` 在数组为空时兼容读取。
- `shipmentRef` 用于追溯该笔尾款关联的出货记录，当前累计金额不依赖该字段分摊。

## 3. 核心口径与公式

### 3.1 合同口径（不会因出货而改变）

```text
SKU 合同货值 = 无变体：数量 × 单价
             有变体：Σ(SKU 数量 × SKU 单价)

其他费用总额 = Σ(费用数量 × 费用单价)
采购合同总额 = SKU 合同货值 + 其他费用总额
```

### 3.2 履约口径（仅实际出货）

```text
有效出货记录 = shipments 中 shipDate 非空的记录
累计已出货 SKU 货值 = Σ(有效出货数量 × 对应 SKU 单价)
已确认费用 = Σ(按每条费用归属规则确认的金额)
累计已出货结算 = 累计已出货 SKU 货值 + 已确认费用
未履约合同承诺 = 采购合同总额 − 累计已出货结算
```

预计出货记录不会影响任何金额。分批出货时，每条有效出货记录会显示自己的“本次应结”，即该次 SKU 货值加本次归属的费用。

### 3.3 现金口径

```text
累计已付 = 实际预付款 + Σ尾款支付记录
当前待付 = max(0, 累计已出货结算 − 累计已付)
预付余额 = max(0, 累计已付 − 累计已出货结算)
合同未付余额 = max(0, 采购合同总额 − 累计已付)
```

“当前待付”表示已履约部分尚未被付款覆盖，不是按自然月计算的会计期间应付。合同未付余额则用于现金规划：即使当前没有待付，仍可看见尚未履约、未来可能需要支付的合同承诺。

## 4. 关键不变量

1. `shipDate` 是履约和结算的唯一生效开关；计划记录只供排期展示。
2. 采购合同总额始终保持合同口径，不会在首次出货后切换为部分出货金额。
3. 当前待付只对已实际出货的结算额负责；预付款超出已履约金额时显示为预付余额，而非误判“已付清合同”。
4. 按数量分摊的费用最多确认一次完整金额；超量出货仅触发数量预警。
5. 负数费用按相同归属规则确认，可降低本次及累计应结。

## 5. 页面展示

每个批次的“付款条款”区分三层：

- **采购合同**：采购合同总额。
- **履约与结算**：累计已出货结算、未履约合同承诺、当前待付。
- **资金**：理论/实际预付款、尾款支付、累计已付、预付余额、合同未付余额。

批次标题同时保留下单 / 已出 / 待出数量，并展示当前待付、预付或合同已付清状态。产品级标题汇总合同总额、累计已出货结算和当前待付。

## 6. 示例

订单为 1,000 件 × ¥100，检测费 ¥5,000，实际预付款 ¥30,000；检测费选择“按数量分摊”。

首次实际发货 400 件后：

```text
采购合同总额      = ¥105,000
累计已出货结算    = ¥40,000 + ¥2,000 = ¥42,000
未履约合同承诺    = ¥63,000
累计已付          = ¥30,000
当前待付          = ¥12,000
预付余额          = ¥0
合同未付余额      = ¥75,000
```

这能同时看清本次需处理的 ¥12,000 与未来仍受合同约束的 ¥63,000，不会把两者混为一个“结算金额”。

## 7. 验证边界

修改计算逻辑时至少覆盖：未出货已付订金、一次/多次部分出货、变体不同单价、正负费用、三种费用归属、超量出货、超付、已全额出货但未付款，以及旧批次费用缺少 `allocation` 的兼容情形。
