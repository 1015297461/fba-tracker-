# 业务逻辑说明

这份文档说明 FBA Tracker 在管理什么、各模块解决什么业务问题、核心业务规则是什么。
"代码怎么实现"见根目录 `CLAUDE.md`；"怎么部署/使用"见 `operations.md`。

## 1. FBA 开发流程（18 个阶段 / 7 个模块）

每个产品（`Product`）的开发进度由 18 个**阶段**（`STAGES`，定义在 `src/data/constants.ts`）描述，
每个阶段归属 7 个**模块 Tab**（`TABS`）之一，对应详情页里的 7 个分页。
阶段状态统一为四种：`未开始` / `进行中` / `已完成` / `暂停`。

| Tab（分页） | 包含阶段 | 业务含义 |
|---|---|---|
| 📋 立项评估 (eval) | 选品立项 → 竞品调研 → 利润测算 → BOM成本拆解 | 决定"做不做这个品"：市场/竞品分析、毛利测算、成本拆解，是否值得投入 |
| 🔢 SKU 变体 (variants) | （非阶段，独立的变体列表） | 一个产品下的多个 SKU（颜色/尺寸等），每个变体可单独跟踪部分阶段（见第2节） |
| 🏭 供应商/打样 (sup) | 供应商开发 → 打样/改版 → 认证合规 | 找工厂、确认样品、走完认证（如 CPC/UL/FCC 等合规要求） |
| 🎨 内容设计 (design) | 包装设计 → 视觉素材 | 包装方案、主图/详情页/A+ 等视觉物料制作 |
| 📦 生产出货 (prod) | 下单生产 → 品控验货 → 出货物流 | 工厂下单、生产批次管理、QC验货、安排海运/空运出货（详见第2节） |
| 🛒 上架运营 (ops) | 关键词研究 → Listing上架 → 产品交接 → 广告推广 | 关键词布局、Listing文案上架、交接给运营、广告投放（"关键词排名"工具服务于此阶段） |
| 🔄 物流与复盘 (review) | 补货物流 → 产品复盘 | 后续补货、整体复盘总结 |

> 阶段顺序大致对应实际开发流程的时间线，但不强制线性——可以并行推进多个阶段，每个阶段独立标记状态/起止日期。

## 2. SKU 变体与生产批次业务规则

### 2.1 变体（Variant）
一个产品可以有多个 `Variant`（颜色/尺寸等 SKU）。变体只在以下 5 个阶段有"自己的"独立数据
（`VARIANT_STAGE_KEYS`）：**利润测算 / BOM成本拆解 / 打样改版 / Listing上架 / 广告推广**——
因为这几项天然按 SKU 区分（不同颜色成本、上架状态、广告表现都可能不同）；其余阶段（如供应商开发、认证）是产品级别共用的。

### 2.2 生产批次（生产出货 → 下单生产 → 生产批次）
"下单生产"阶段下可以建多个**生产批次**（一次工厂下单 = 一个批次），每个批次包含：

- **基本信息**：批次号、工厂、下单日期、预计出货日期
- **SKU 明细**：
  - 无变体的产品：直接填数量+单价
  - 有变体的产品：按 SKU 拆分数量+单价（"SKU 明细"表格）
- **其他费用**：代采配件、运费等额外成本，与 SKU 小计相加得到批次总金额；数量/单价支持负数（如扣除供应商违约赔付金额），一旦该批次有出货记录，其他费用会整笔计入"实际出货结算"金额
- **付款**：定金/尾款比例（按批次总金额算出"理论"金额），加上实际定金支付、可分多笔记录的尾款支付——付清状态以"实际支付总额 ≥ 结算金额"判断

### 2.3 出货明细与"待出货/已到货"统计规则 ⚠️
每个批次下可以记录多条**出货明细**（一次出货 = 一条记录），包含预计出货日期、**实际出货日期**、
发运方式、运单号，以及本次出货的 SKU 数量拆分。

**核心规则：只有「实际出货日期」非空的出货记录，其数量才计入各类统计**——包括：
- 批次的"已出"数量、"待出货"数量（= 下单数量 − 已出数量）
- 每个 SKU 的"实际到货"数量、"待出货"数量（= 该 SKU 下单数量 − 实际到货数量）
- "实际出货结算"金额（用于判断付款是否结清）
- "超出订单数量"预警

也就是说，**预先创建的出货记录（计划中、还没实际发货，日期留空）不会影响"已出/待出/到货"等数字**，
只有真正发生（填上实际出货日期）才算数。出货记录自身展示的数量（如该条记录的 SKU 拆分小计）不受此规则影响，始终如实显示填写内容。

## 3. 工具模块业务定位

工具模块是独立于"产品开发流程"之外的辅助调研/监控工具，通过本机直连抓取亚马逊页面获取数据。

### 3.1 关键词排名（服务于"上架运营 → 关键词研究/广告推广"）
- **解决的问题**：自家 Listing 在某个关键词下的自然排名 / 广告位排名是否在变好或变差。
- **典型用法**：为某个 ASIN + 站点配置一组关键词，系统每天定时（0/6/12/18点）抓取一次搜索结果页，
  记录该 ASIN 的自然排名与广告排名，按"关键词 × 时间"画出趋势，用于判断关键词布局/广告投放效果。
- **数据来源**：本机网络直连抓取（非第三方 SERP API/ERP代理池），适合低频小规模监控；
  若未来需要更高频或更大规模，需要切换到付费 SERP API 或住宅代理。

### 3.2 产品采集（服务于"立项评估 → 竞品调研"）
- **解决的问题**：选品/竞品调研时，需要批量收集一批竞品（或对标产品）的详情页信息做对比分析。
- **典型用法**：粘贴一批 ASIN（指定站点、是否连带抓取评论），一次性批量抓取标题、价格、评分、
  评论数、五点描述、详情、主图/图集/A+图片、规格参数、Best Sellers Rank、顾客评价摘要等，
  落库后表格展示，可点击"详情"弹窗预览（含图片画廊），用于选品对比、定价参考、卖点提炼。
- **失败重试**：抓取失败的 ASIN 可单独重试，结果按 ASIN 合并回原列表，不丢失已成功的部分。
- **结果搜索**：采集结果列表顶部提供 ASIN 搜索框，输入时实时过滤，badge 同步显示过滤条数/总条数。
- **反爬说明**：Amazon 有时返回"Dog page"（HTTP 200 但内容为错误页），与 CAPTCHA 一样触发 session 重置（清空 cookies、重新初始化）再重试，避免用同一"已标记"身份持续重试失败。

### 3.3 评论采集（服务于"立项评估 → 竞品调研 / 上架运营"）
- **解决的问题**：批量获取指定 ASIN 的买家评论，用于分析竞品口碑、提炼痛点/卖点、指导 Listing 优化。
- **典型用法**：输入一批 ASIN（指定站点），配置排序方式（最新/最有帮助）、星级过滤（1-5星或全部）、
  是否仅抓取"已验证购买"评论、最大抓取页数，批量抓取后按 ASIN + review_id 去重落入评论池，
  支持跨任务复用（同一 ASIN 的评论在数据库层合并，不重复插入）。
- **数据字段**：评分、标题、作者、日期、正文、有帮助票数、评论图片。

### 3.4 PDF 拆分（通用文档处理工具）
- **解决的问题**：供应商/货代提供的 PDF 文件页数过多，需要按页码范围拆分成多个小文件分发或上传。
- **典型用法**：批量上传多个 PDF → 每个文件独立配置拆分方式 → 选择输出目录 → 一键拆分。
- **拆分方式**：
  - **按最大页数**：指定每份最多 N 页，可限定处理页码范围（起始页~结束页），依次生成 `_001.pdf / _002.pdf ...`
  - **自定义范围**：指定多段页码（如 `1-50, 51-200`），每段生成一个文件，命名为 `_p1-50.pdf`
- **输出目录**：
  - 选"原文件目录"时立即弹出 macOS 原生文件夹选择框，引导用户定位到源文件所在目录
  - 选"自定义"时手动点击"浏览"选择任意目录
- **依赖**：后端需 `pypdf`（`pip3 install pypdf`）；目录选择通过 `osascript` 调用 macOS 系统对话框。

## 4. 产品回收站（软删除）

- **解决的问题**：局域网多人协作场景下，误删产品（或删完发现删错了）无法找回，之前是硬删除、无法挽回。
- **行为**：在产品列表删除一个产品后，产品不会立即从数据库消失，而是先进入侧边栏底部"回收站"入口。回收站里可以：
  - **恢复**：把产品完整还原回产品列表（包括其所有阶段数据、变体、生产批次等）。
  - **彻底删除**：仅从回收站移除该产品快照，不可恢复。
  - **清空回收站**：一次性彻底删除回收站里的所有产品，不可恢复。
- **没有自动过期机制**：回收站里的产品会一直保留，直到有人手动恢复或彻底删除/清空，不会像很多系统那样"N 天后自动清空"。
- **多人协作影响**：删除产品（进回收站）和恢复产品都会推进全局 `version`，其它终端下一次轮询/编辑时会感知到列表变化，行为和其它产品字段编辑一致。
