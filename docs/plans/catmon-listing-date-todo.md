# TODO：类目榜单「上架时间」列

> 状态：**未实现**（2026-10-30 只做了调研与方案，先记档，后续再落地）
> 目标模块：AI 分析 · 类目榜单监控 → 榜单列表

## 需求

榜单列表增加「上架时间」列；可排序；空值显示 `—`。
点击者会在分析"新品速度 / 老品占比"时用到这一列。

## 已核实的事实（都是实测，不要再重复验证）

1. **榜单页 / 搜索页没有该字段**
   搜索页 1.6MB HTML 里 `Date First Available` 出现 0 次；bestsellers 网格只有 rank/标题/价格/评分/评论/图。

2. **详情页有时有、有时没有**
   - 有：`Date First Available : March 22, 2022`（规格表里）
   - 没有：抽查 `B0BW9L8ZGK`、`B01BF3XU70` 两页，`Date First Available` 出现 **0 次**，`product_details` 全空。
   - ⇒ **详情页不能当"校正工具"**，此前的「点开详情回写精确日期」方案已否决。

3. **SIF 的「上架天数」与「上架日期」是同一个数**
   10 个 ASIN 对撞：`今天 − listed_age_days` 与 `first_available_day` **10/10 逐日完全一致**。
   ⇒ 用天数反推**不会**更精确，它只是把日期减回去。

4. **"月初（xx-01）"来自上游数据本身，不是 SIF 降精度**
   亚马逊该字段允许只到月（老品/批量上传/变体常见），SIF 只能忠实填 1 号。
   全库占比：`age` 来源 3.3%（≈1/30 自然概率）、`asin` 来源 4.9%——**不是系统性问题**。

5. **SIF 额度**：`market_get_asin_profile` = **2 点/ASIN**，单次最多 20 个。
   一个榜单 100 条 ≈ 200 点；两个榜 ≈ 400 点。日常增量通常 10~40 点/天。

6. **现成缓存可直接复用**：`rmon_asin_meta` 已有 1302 行 / 1295 条有日期（覆盖率 99.5%）。

## 方案（待实现）

**存储：属性入属性表，事实不入每日快照**

- 复用 `rmon_asin_meta`（`asin PK / first_available_day / brand / fetched_at / src`），
  把它视为**全局 ASIN 属性表**（名字带 `rmon_` 是历史包袱，不改名，文档标注即可）。
- **不要**往 `catmon_items` 加快照列：上架时间不变，100 行/天纯冗余；
  要看"某天在榜时已上架多少天"，现算 `当天 − 上架日期` 即可。

**取数：先查库，缺的才问 SIF（与排名监测同一套）**

1. 抽出 `backend/asin_meta.py`：`ensure(asins, country="US", max_new=40)`
   - 读库 → 命中的直接返回（0 成本）
   - 缺的按 **20 个/批** 调 `sif_fetcher.asin_profiles`
   - 写库；**负缓存**（查过没有就写空串，避免反复扣点）
   - 全局锁：防并发重复请求；`max_new` 单次上限护栏
2. 触发时机：`_run_target` 保存快照后**异步**补齐（不阻塞采集状态落 ok），日志节流。
3. 接口：`/api/catmon/snapshot`、`/matrix` 的返回里直接带 `firstAvailable`，前端不做二次请求。

**前端**

- 列名「上架时间」，可排序（空值恒排最后），空值 `—`
- 月初日期显示 `2023-03` 并加 `~` 或 hover 说明"可能只到月"
